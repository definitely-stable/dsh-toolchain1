# M2 Oracle v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and freeze an independent exact-target API truth/adjudication v2 for M2.3, then use it only after the freeze barrier to derive an offline interpretation of the immutable retained P0 observations.

**Architecture:** Truth v2 is evaluation-only and derives the reachable public API directly from the frozen `ordinary-workspace.json` package manifests and `.d.ts` bytes using an independent TypeScript AST implementation. It must not use the production Contract Index/retrieval normalization as truth. Claim parsing, API classification, and task-success adjudication are separately versioned; the corrected oracle is frozen before any bulk re-adjudication of retained P0 outputs.

**Tech Stack:** TypeScript 6 Compiler API, Node.js 22/24/26, Vitest, canonical SHA-256 evaluation identities, JSON evaluation contracts.

**Spec:** `docs/evaluation/m2/agent-comparison-amendment-2026-08-30.md`, Issue #64.

## Global Constraints

- Do not modify `docs/evaluation/m2/api-oracle-v1.json`, `docs/evaluation/m2/agent-pilot-p0.json`, or retained run `33264398212`.
- Do not call `createFrozenM2RetrievalIndex()` or use production `ContractIndex` facts as the Truth v2 authority.
- Truth v2 must contain no P0 task ids or task-specific symbol exceptions.
- Do not change production retrieval ranking, target/index fingerprint semantics, B ordinary tools, provider limits, or H1 commitment in this slice.
- Missing or unresolved authoritative public declaration coverage is `UNKNOWN`, never inferred absence.
- Freeze Oracle v2 identities before bulk applying v2 adjudication to historical answers.
- No provider/model/network call is permitted for Truth v2 or offline re-adjudication.
